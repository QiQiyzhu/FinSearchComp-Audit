# ATLAS-Fusion：20 题跨轨迹证据仲裁

这是对已锁定的 [20 题 × 5 策略真实 Web Search 实验](../live_pilot_20q_atlas_sonnet5_20260813/README.md)
所做的探索性第二阶段。每道题把五条独立搜索轨迹交给同一个 `claude-sonnet-5` 做 listwise
证据仲裁，不新增搜索，不读取 `gold_answer`、记录来源或参考证据。

## 结果

| 方法 | 最终决策准确率 | 模型仲裁初稿准确率 | 回答覆盖率 | Gate 触发率 |
|---|---:|---:|---:|---:|
| 同轮普通搜索 Agent | 55% | 55% | 75% | 0% |
| 单轨迹 ATLAS-RAG v1.1 | 45% | 45% | 50% | 10% |
| **ATLAS-Fusion** | **55%** | **65%** | **65%** | **15%** |

最终 55% 与普通 Agent 持平，按题配对差为 0 个百分点，bootstrap 95% CI 为
`[-20pp, +20pp]`。因此不能声称 ATLAS-Fusion 已在最终准确率上超过普通搜索。

但仲裁初稿达到 65%，等于五条输入轨迹“至少一条初稿正确”的 oracle 上限 13/20，说明跨轨迹
融合成功利用了互补证据。最终 Gate 又把 3 条初稿改为拒答，其中 Nasdaq–S&P 差值和
Activision 三年资本开支比例两条在当前容差下是正确初稿；这将瓶颈定位到“派生答案的单位
与底层证据单位不同”以及拒答校准。由于这是在看过当前 20 题结果后发现的机制，本仓库不再
用同一题集调整阈值并重报主结果；下一步应在新题开发集上定义派生单位规则，再用独立测试集验证。

## 成本与可审计性

- 新增 20 次结构化仲裁 HTTP 请求；
- 不新增 Web Search，复用五策略主实验的 214 次真实搜索；
- 每题输入 5 条独立轨迹；20 题共引用 753 个去重来源条目和 172 条去重原生 citations；
- 所有 20 个仲裁单元成功，实际模型一致；
- 每条记录保存输入包 SHA-256、响应 ID、输出、审计状态和本地 raw response SHA-256；
- 单元测试检查 prompt packet 不包含 `gold_answer`、基准 `source_url` 或参考证据字段；
- 输出证据 URL 必须属于五条输入搜索轨迹，否则运行立即失败。

## 与 20×5 主实验的关系

ATLAS-Fusion 的计算预算显著更高：它消费五条各自最多 3 次搜索的既有轨迹，再增加一次模型
仲裁。因此它是“更高成本的探索性融合”，不能作为与普通 Agent 同预算的主要对照。公平的
主结论仍来自 20×5 实验：单轨迹 ATLAS 从同轮完整验证器的 35% 提高到 45%，但低于普通
Agent 的 55%；ATLAS-Fusion 在更高计算预算下追平普通 Agent，并把初稿上限提高到 65%。

## 文件

- `case_outcomes.csv`：20 道题的仲裁动作、答案、正确性和输入规模；
- `metrics.json`：聚合指标及相对普通 Agent 的配对区间；
- `trace.jsonl`：20 条标准化仲裁 trace；
- `study_manifest.json`：冻结协议、来源协议哈希、预算和完成状态。

原始响应保留在本地并由公开 trace 中的 SHA-256 标识，不提交 API 密钥或 raw response。
