# Claude 真实 Web Search Agent：10题 × 4策略 Pilot

> **已归档：** 这是运行中途发布的前 10 题结果。正式项目展示已由
> [完整 20题×4策略结果](../live_pilot_20q_claude_complete/README.md)替代；
> 本目录仅保留用于追踪研究过程，不应再作为主结果引用。

> 这是 10 个真实金融问题、4 个策略、1 个模型、1 次重复的外部有效性 pilot。
> 它替代此前的 1 题能力样例，但仍不是完整 benchmark 或模型排名。

## 一句话结论

真实 Claude Web Search Agent 与完整 trace 协议已经跑通；但在开放网页上，
严格元数据 gate 因发布日期和版本字段经常缺失而过度拒答，最终准确率低于普通
Agent。这说明下一阶段的主要瓶颈不是“再加一层规则”，而是可靠地提取和验证网页
元数据。

## 真实结果

| 策略 | 有效运行 | 回答覆盖率 | 最终正确率 | 模型初稿正确率 | 已采用证据时间泄漏 | 日期缺失 |
|---|---:|---:|---:|---:|---:|---:|
| 普通搜索 Agent | 10/10 | 90% | **70%** | 70% | 0% | 88.9% |
| 时间约束 Prompt | 10/10 | 90% | **70%** | 70% | 0% | 55.6% |
| 元数据过滤器 | 10/10 | 50% | 50% | **70%** | 0% | 0% |
| 完整证据验证器 | 10/10 | 30% | 30% | 60% | 0% | 0% |

所有已回答记录的 API citation 覆盖率为 100%，所有 40 条记录都保存了完整搜索
来源。`日期缺失` 只对最终回答采用的证据统计；严格 gate 接受的证据日期完整，
但大量问题因此被拒答。

## 如何解释这个反转

受控 100 条实验中，日期、期间、版本和单位都是显式、完整且人工标注的，
因此 TEG 可以达到设计上限。真实网页中则不同：

- 普通 Agent 和时间 Prompt 经常在没有明确发布日期的情况下继续回答；
- 元数据过滤器的模型初稿正确率为 70%，经过 gate 后降至 50%；
- TEG 的模型初稿正确率为 60%，经过 gate 后降至 30%；
- 严格策略拦截了带未来日期的候选证据，但也因缺失元数据误杀可用答案。

因此当前证据支持的结论是：

> 显式 gate 能降低采用已知不安全证据的风险，但仅依赖模型自报的网页元数据会造成
> 明显的覆盖率和准确率损失。

不能声称 TEG 已经优于普通 Agent，也不能用 10 道题判断真实模型排名。

## 研究边界与下一步

1. 样本只有 10 题、1 个模型、1 次重复，不能做显著性或稳定性结论；
2. 子集是在运行中根据费用停止后确定的“数据集前 10 题完整前缀”，不是预注册样本；
3. 网页发布日期仍主要来自模型结构化报告；
4. 下一步应独立抓取官方页面/文件元数据，对缺失字段使用校准风险而非一律拒答；
5. 扩大问题与重复次数后，才报告均值、标准差或 bootstrap 区间。
