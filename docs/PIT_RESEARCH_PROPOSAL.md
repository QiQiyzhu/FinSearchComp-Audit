# 金融 Point-in-Time Benchmark：研究提案与工作台迭代

日期：2026-09-26。用途：向导师汇报研究切入点、现有基础与第一阶段实验。本提案中的论文方法均为参考，尚未完成论文复现；候选贡献的新颖性和实验范围需与导师确认。

[打开交互试点](https://qiqiyzhu.github.io/FinSearchComp-Audit/workbench/pit.html) · [首次真实运行结果](PIT_PILOT_RESULTS.md) · [冻结实验协议](PIT_PILOT_PROTOCOL.md)。建议汇报时先演示一题的前后时点，再讨论研究问题和后续数据范围。

## 1. 拟研究什么

拟将现有 FinAgent 金融工作台升级为**金融时间截面评测与证据审计平台**：给定一个历史时点，检查金融回答是否采用当时可得的正确版本证据，并独立观察模型对不同时期金融事件的知识表现。

这一方向与组内“从研报、新闻构造按月或周组织的题目，观察模型时间截面前后表现”相衔接。工作台提供数据审阅、题目回放和错误分析界面；研究主体是可检验的协议、数据与对照实验。第一阶段先使用已有 SEC 财务资料建立小规模、可重跑的实验链路，再扩展至新闻和研报。

必须区分两个概念：**证据在当时可得，不代表模型只知道当时的信息；模型在某个月表现下降，也不直接证明其真实训练数据止于该月。** 当前模型加上历史日期提示，并不会成为在该历史日期训练完成的模型。

## 2. 两条赛道分别回答问题

| 赛道 | 固定什么、改变什么 | 主要测量 | 结论边界 |
| --- | --- | --- | --- |
| A：时点证据合规 | 固定问题、模型与目标来源，改变 `as_of`、检索过滤和文档版本 | 数值正确、引用正确、时间合规、应拒答时能否拒答 | 衡量系统执行证据契约的能力；不推断模型训练截止 |
| B：模型时间知识画像 | 禁止检索，固定模型版本和采样条件，按事件首次公开时间组织题目 | 每月/周正确率、拒答率、猜测基线、日期线索敏感性；条件满足时估计表现断点 | 得到任务相关的行为知识边界估计；不是训练语料审计 |

赛道 A 中，`as_of` 是一个问题的证据使用边界；赛道 B 中，题目所对应的首次公开时间是观察模型知识随时间变化的横轴。两者应分别展示、分别计分。检索帮助模型回答新事件的效果，可以另作开放证据条件的对照，不能混入闭卷知识画像。

## 3. 研究问题与可证伪假设

**RQ1：在披露和修订边界附近，严格时间过滤与版本选择，能否减少不合规回答，同时保留可回答题的正确率？**

后续完整实验比较四种条件：普通检索、仅增加日期提示、严格时间过滤、时间过滤加版本解析。预期最后一种条件减少未来证据引用和错误版本使用；若同时明显增加可回答题的错误拒答，就不能只凭泄漏率降低宣布改进成功。数据按独立披露事件划分开发集与测试集，并对同一事件派生出的题目成组统计。

**RQ2：金融事件上的行为知识边界，是否随题型、实体热度与日期提示发生变化？**

选取无法从惯例提前确定的事实问题，按月分层；比较原始问题、日期遮蔽、实体匿名化和数值反事实条件。若模型面对反事实证据仍坚持真实历史答案，可进一步分析证据服从与记忆影响；这种现象本身不提供训练来源证明。先报告带样本量的正确率和拒答率，待时间覆盖、题目难度控制与重复运行充分后，再考虑变点检测与敏感性分析。

可能的贡献是：金融资料的版本与可得时点标注规范、按事件配对的前后时点题集、将证据合规和闭卷知识画像分开报告的评测协议，以及可回放的审计工作台。是否达到论文贡献要求，需在进一步对比相关工作后由导师评估。

## 4. 相关研究：借鉴什么，暂不声称什么

以下来源于 2026-09-26 查阅的一手论文和官方项目。正式发表与预印本分开注明；本文没有继承这些工作的实验分数。

| 工作与日期 | 与本项目相关的方法 | 本阶段采用范围与限制 |
| --- | --- | --- |
| [ExAnte: A Benchmark for Ex-Ante Inference in Large Language Models](https://aclanthology.org/2026.eacl-long.72/)，EACL 2026，3 月 | 将历史时点约束下的任务表现与未来信息泄漏分开评价；覆盖问答、股票预测等任务 | 作为主要问题定义参考：正确答案与时间合规应分开测。本轮只做限定来源财务问答，未复现其任务集或泄漏率实现 |
| [LLMLagBench](https://arxiv.org/abs/2511.12116)，2025-11-15，预印本 | 从新闻筛选时间敏感事实题，使用 PELT 检测多个表现断点，单独观察拒答 | 借鉴按月画像和拒答分离。题库未公开；不能声称复现，更不能用少量题测出精确训练截止 |
| [HindsightBench](https://arxiv.org/abs/2607.18867)，2026-07-21，8 月修订，预印本；[代码](https://github.com/Khaozhe/hindsightbench) | 日期明确、仅日期、日期遮蔽、日期移植四臂对照，加日期恢复和结果回忆探针 | 借鉴对照设计及模型配置记录。遮蔽线索没有删除参数知识；其结论也具有任务条件限制 |
| [Scaling Point-in-Time Language Models](https://www.nber.org/papers/w35247)，NBER 工作论文，2026-05；[论文版本](https://arxiv.org/abs/2607.11889) | 用按时间过滤的语料训练历史模型检查点 | 用于界定真正时点模型与日期提示的差别；未来可尝试小模型对照。本阶段没有重训模型 |
| [LiveBench](https://livebench.github.io/)，ICLR 2025 | 持续更新题目、客观答案评分、延迟公开最新测试题 | 借鉴滚动冻结与公开开发集/保留测试集分离；更新题库只能降低污染风险，不能证明无污染 |
| [Look-Ahead-Bench](https://arxiv.org/abs/2601.13770)，2026-01-20，预印本；[代码](https://github.com/benstaf/lookaheadbench) | 在金融工作流中比较不同时间区间表现，并加入数量基线 | 借鉴跨时间对照；收益或性能衰减也受环境变化影响，本轮不做交易收益实验 |
| [UnSeenTimeQA](https://aclanthology.org/2025.acl-long.94/)，ACL 2025，7 月 | 用合成事件区分时间推理与真实世界记忆 | 可用于修订链、顺序事件的合成压力测试；合成题不能替代真实金融资料评估 |

## 5. 已有基础与旧成绩的使用方式

目前仓库已有 SEC 年度事实适配、期间与申报日过滤、确定性财务计算、证据 ID 与来源哈希、工作台展示、任务保存与回放。这些是搭建赛道 A 的工程基础；现有模型主要参与受限事实选择，不能将产品输出质量直接解释为通用 LLM 的金融研究能力。

旧工作台内部 40 题评估记录了首评与修复后回归的区别，具体定义和局限见[工作台质量协议](WORKBENCH_QUALITY.md)。本提案不重新核验或背书旧成绩，不把它当作本轮 PIT 成绩，也不把已公开题目再次标成未见测试集。仓库中的其他历史实验同样保留其原始模型、数据与协议归属。

现有原始 SEC Company Facts gzip 抓取于 2026 年，再按申报日期筛选历史记录；它们不是 2024 年当时保存的整库快照。可以审计所选 accession 的结构化事实，尚不能证明当时全部可见网页、新闻与研报均被完整保存。

## 6. 本轮最小 Pilot：6 题 × 2 时点 × 3 条件

本轮以 Microsoft、Apple、NVIDIA 的 FY2024 **营业收入、营业利润率**各一题，共 6 个基础问题。每题使用指定 10-K accession，分别设置申报日 D 的前一天与后一天，并运行 `closed_book`、`unfiltered`、`pit_filtered` 三种条件，共 **36 条运行记录**。这 36 条不是 36 个独立事件，不能据此推断广泛金融场景的稳定效果。

| 公司、FY2024 实际期间 | 指定 accession；申报日 D | 前/后时点 | 字面收入 / 营业利润，USD |
| --- | --- | --- | --- |
| MSFT：2023-07-01—2024-06-30 | `0000950170-24-087843`；2024-07-30 | 2024-07-29 / 2024-07-31 | `245122000000` / `109433000000` |
| AAPL：2023-10-01—2024-09-28 | `0000320193-24-000123`；2024-11-01 | 2024-10-31 / 2024-11-02 | `391035000000` / `123216000000` |
| NVDA：2023-01-30—2024-01-28 | `0001045810-24-000029`；2024-02-21 | 2024-02-20 / 2024-02-22 | `60922000000` / `32972000000` |

收入使用字面金标准；营业利润率由独立评分逻辑以 `100 × Fraction(营业利润, 营业收入)` 核验，最终显示精度与容差按协议固定。不能让被测模型或产品计算器自己生成自己的金标准。原始证据分别保存在 [MSFT.json.gz](../research_workbench/data/upstream/MSFT.json.gz)、[AAPL.json.gz](../research_workbench/data/upstream/AAPL.json.gz)、[NVDA.json.gz](../research_workbench/data/upstream/NVDA.json.gz)，审计需要匹配 accession、标签、单位、数值、期间和申报日，并记录文件哈希。

三种条件的含义：`closed_book` 不提供证据，观察当前模型的回答；`unfiltered` 提供未按截止日过滤的目标证据，构造可识别的时间冲突；`pit_filtered` 仅提供指定范围内截至该时点可用的证据。前时点的严格证据条件应报告缺少目标文件，后时点应能依据文件回答。闭卷数字正确、证据引用正确和时间合规是不同指标，不能合并为一个“准确率”。

**这个边界是指定文件的可得边界，不必是数值首次公开的边界。** 财务数字可能先在业绩公告或其他文件中发布，因此申报前回答出相同数字，不能单独证明模型使用了未来知识。本轮问题及评分需明确“依据指定 accession、截至给定日期”的证据契约；也不评估申报当日的分钟级可得性。

完整输入、评分规则和执行入口见 [Pilot 协议](PIT_PILOT_PROTOCOL.md)；交互回放入口为 [PIT 工作台](../site/workbench/pit.html)，机器可读展示数据为 [pit_pilot.json](../site/workbench/data/pit_pilot.json)。**运行是否完成、实际调用模型、成功/失败条数及分数，均以运行记录为准；本文不预填实验成绩。** Pilot 主要验证数据、执行、评分和展示是否衔接，不足以回答 RQ2。

## 7. 新闻与研报扩展时必须处理的时间问题

| 字段或问题 | 需要保留的含义与处理方式 |
| --- | --- |
| `event_time` / `period_end` | 事件发生时间或经济期间结束；不能当成信息公开时间 |
| `first_published_at` | 目标事实首次公开的可核验时间；文章提及旧事件，不等于文章中的答案那时已知 |
| `revision_published_at` / 版本链 | 更正、补充、重述何时公开；每个正文版本独立保存，不用最新网页覆盖旧版本 |
| `retrieved_at` 与来源哈希 | 本系统何时获取哪一份内容；抓取时间不能替代首次公开时间，旧发布日期不能证明今日正文当时存在 |
| 来源、定位与授权 | 保存原始链接、页码/段落、发布时间证据及可公开范围；无法发布全文时，至少保留允许发布的标注和定位 |
| `evaluated_at` 与模型配置 | 记录模型标识、端点、采样、提示词、工具条件与实际运行时间；固定名称的 API 也可能更新 |

宏观题可考虑 [ALFRED 的历史版本接口](https://fred.stlouisfed.org/docs/api/fred/series_observations.html)，它支持按指定历史日期获取当时的数据版本；不能用今天的最终修订值替代当时公布值。

数据切分应以事件及其报道链为单位，避免同一公告的改写题分别进入开发集和测试集。新题先冻结，再运行模型；首次结果、失败和修复后回归分别保存。模型辅助出题只生成候选，日期与答案由规则核验及人工复核。若周/月样本稀少、难度不均或断点不稳定，就只报告观察数据，不给出“精确 cutoff”。

## 8. 与 Pronoia 的协作切入

[Noia-Labs/Pronoia](https://github.com/Noia-Labs/Pronoia) 在本次查阅时重定向至 [textmind/Pronoia](https://github.com/textmind/Pronoia)。其官方 README 描述了对话式事件研究、证据卡片、事件回测及 Arena 对比；本提案仅核对公开文档，没有验证其性能或完成系统集成。

可先贡献一个边界明确的接口：输入事件、历史时点与可用证据包，输出模型回答、引用、工具轨迹和时间违规检查结果。让 Pronoia 作为被测系统之一，复用其事件案例；本工作台负责冻结证据和回放评分。这样可以同时服务 PIT 研究和组内事件分析项目，具体数据、接口和共同实验应与维护者及导师协商。

## 9. 四周交付计划

下面是建议安排，不代表已完成或已经安排自动执行。样本量需结合可获得的数据与复核时间调整，优先确保时间标注可靠。

| 周次 | 具体交付 | 可检查的完成标准 |
| --- | --- | --- |
| 第 1 周：协议与小样本 | 完成 36 条 Pilot 的运行审计；与导师确认研究问题、数据范围和标注表；审阅首批新闻/研报候选 | 输入和金标准冻结、原始响应可查、失败保留；能够解释每个截止时点为何可答或不可答 |
| 第 2 周：版本数据与题集 | 扩展 20–30 个独立披露/更正事件；目标 100–150 个时点问题；建立按月索引和按事件隔离的测试集 | 每题有来源版本、时间依据、字面答案或公式；抽样双人复核，争议题单列 |
| 第 3 周：对照与消融 | 在固定模型上比较时间提示、过滤、版本解析；条件允许时增加第二个模型；保留一组独立新题 | 报告正确率、错误拒答和时间违规的完整分母；按事件分析，记录成本、延迟和失败 |
| 第 4 周：分析与汇报 | 交付可回放的网页、数据说明、错误分类和初步报告；对 RQ2 做按月闭卷试测；提出后续实验 | 能逐题解释改进来源和失败；月度样本不足时不拟合精确边界；首次评估与回归清楚区分 |

第一阶段未包含大规模新闻/研报抓取、成熟的月/周知识曲线、精确模型训练截止估计、投资收益验证或完整 Pronoia 集成。若数据版本证据不足，优先缩小数据范围并报告缺口。

>
> 我准备把问题分成两部分：第一，当我们要求模型站在某个历史日期回答时，它是否用了当时可得、版本正确的资料；第二，关闭检索后，模型对不同月份金融事件的知识表现怎样变化。这两部分分别对应证据时间合规和模型时间知识画像，不能把历史日期过滤直接当作测出了模型训练截止。
>
> 我参考了 ExAnte、LLMLagBench 和 HindsightBench 等工作。本轮已完成三家公司、六个财务问题的三十六次真实调用。一个值得进一步研究的观察是：删掉未来财报材料后，模型在六个前时点问题上仍全部给出数字。检查发现，过滤同时删掉了申报日期，而提示允许模型凭自身知识回答；因此还不能把效果归因于过滤本身，下一轮需要分离时间元数据与记忆许可。这仍是三个事件的小试点，不是模型知识截止证明。

> 接下来我想用四周扩展到有可靠发布日期和修订版本的新闻、公告或研报，形成按事件隔离的测试集，分别报告正确率、拒答和时间违规。也希望把这套时点评测接口用于 Pronoia。想请老师帮我确认：应优先聚焦证据合规，还是模型知识边界，以及哪些数据和题型最有研究价值。
