## 题集和金标准怎样固定

评估代理先独立阅读官方财报和完整 SEC 原始响应，写入 **34 个字面年度数值**，再用 Python 标准库 `fractions.Fraction` 独立核验派生答案。评分器不导入产品的规划器、选数器或计算器；引擎子进程只收到问题、公司与截止日，收不到金标准。

题集含 20 道开发题、20 道保留题，覆盖中文和英文、年度金额、同比、增长金额、百分点变化、利润率、研发费用率、现金转换率、自由现金流、多意图、多期间、缺失口径、非年度问题、非金融请求和申报日期前后一天。对两家公司比较、方向性研究信号、新闻检索及定性判断另做功能检查，**不纳入这 40 题的数值成绩**。

[manifest](../evals/workbench/manifest.json)于 `2026-09-22T12:47:51Z` 固定题目和金标准文件哈希。冻结发生在首次查看 v1/v2 输出之前；当时 v2 工程开发已并行开始，因此不能声称从研发开始就完全盲测。实现代理未阅读保留题和答案，开发集通过后由主代理宣布代码冻结，再首次运行保留集。隔离依靠协作协议，仓库没有物理权限隔离；这不是第三方主持的基准。

v1 从真实提交 `d8ae038` 通过 `git archive` 提取，运行前逐文件核对。两版使用相同的原生 `demo_companyfacts.json`：为兼容 Windows / Linux 的 Git 换行转换，仅统一 CRLF 为 LF 后逐字节比较，其他字节必须一致。样本只收录三家公司 FY2023/FY2024 的既定年度标签。完整原始 gzip 只供评分器审计，不注入运行时扩充答案范围。本轨道缺少 FY2022 时应明确保留判断，不能换成 FY2023；这衡量数据范围诚实性，并非宣称系统原则上不能比较非相邻年度。

## 怎样判分

- **完整问题满足**：全部所求数值、单位、年度端点正确，原始证据有效，必要操作数有引用，答案区实际呈现，且没有错误拒答。v1 检查摘要中的对应事实；v2 检查按问题生成的 `answers`。通用指标表恰好含有相关数字，不能替代摘要或答案区漏掉的请求。
- **所求数值正确率**：分母固定为题目要求的 35 个值；缺少答案计错。额外生成的正确数字不增加分子。评分器不替引擎从其他数字计算它遗漏的答案。
- **正确拒答**：必须明确标识未完整覆盖，并提供缺口原因；运行异常不算正确拒答，也不允许输出被禁止的未来期间数字或混用定义的自由现金流。部分背景事实可以保留。

首评两道失败均有正确来源，但没有回答所需运算：

1. `H05`：“How many dollars did Apple's revenue increase from FY2023 to FY2024?” 返回年度金额和增长百分比，漏掉美元增长金额。
2. `H10`：“What percentage of Apple's FY2024 revenue was spent on R&D?” 返回收入及研发金额，漏掉研发费用率。

这两题随后已向实现代理公开，任何修复后的重跑都属于**评估后回归**，不能再称未见保留集成绩。首次结果和网页主分数保持不变。

修复后的[评估后回归结果](verification/workbench-quality-v2-post-eval-regression.json)为完整满足 **40/40**、所求数值 **35/35**，原始证据和时间审计 **40/40**。这是已经公开题目上的回归成绩，不用来替换首次 38/40 的结果。

## 离线复现与 CI

需要 Python 3.11、`requirements-workbench.txt` 依赖与包含 `d8ae038` 的 Git 历史（GitHub Actions 使用 `fetch-depth: 0`）。运行期间清除相关密钥环境变量，使用 `Settings()` 默认关闭外部服务，并阻断 socket 连接；任何连接尝试或 `model.used` 都令评估失败。

```bash
python -m unittest discover -s evals/workbench -p 'test_*.py' -v
python scripts/evaluate_workbench.py --split all --output build/quality/ci-evaluation.json --require-no-regression docs/verification/workbench-quality-v2-first.json
```

重放首评单公司检查点可运行：

```bash
python scripts/evaluate_workbench.py --split all --current-ref 7f4890d084ba4dbbff5553400fbfd379cd7c007d --output build/quality/first-replay.json
```

评分器的 8 个诚信检查覆盖错误数字、未知引用、篡改原始值、提前一天使用申报数据、错误拒答、异常冒充拒答，以及用无关指标表掩盖漏答。CI 要求首评已满足的问题不退步、数值正确总数不下降、全部证据继续通过；不删除两道首评失败来制造满分。保留集结果文件禁止覆盖，复跑应换用新的输出文件名。完整运行输出只写入被忽略的 `build/quality/`。

本评估不测开放网页搜集、DeepSeek 证据选择、并发吞吐、模型幻觉率、跨全部 SEC 标签泛化、投资收益或概率校准。下一轮需要新增并再次冻结更多发行人、负分母、重述和自定义标签案例，并由独立评估者制作新的未见问题；当前 40 题已经成为回归集。
