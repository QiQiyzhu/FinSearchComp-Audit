# 对旧 PIT 输出施加证据门：系统干预回放

这轮实验重新使用先前 6 道题、3 份申报、36 次 DeepSeek 调用留下的完整请求和输出，**没有新增模型、检索或网络调用**。它评估的是系统输出策略的变化，不是模型能力提升，也不是新的独立准确率评测。

完整结果：[干预记录](verification/pit-gate-replay-v3.json)。原始模型输出和旧评分文件保持不变。

## 干预内容

先按原始 trace 完整重放，验证旧请求、响应、代码指纹和评分与已发布结果一致。之后，每一项门禁只接收该次调用原来已提供的材料、截止日、所问指标/公式和原始结构化响应。**门禁不读取 gold、试验前后阶段标签或条件名称来决定是否接受。**

接收一个数值需要同时满足：

1. 引用存在于该次请求实际提供的材料中。
2. 所需全部操作数均已引用；公司、accession、期间、表单类型和单位一致。
3. 每份被引申报从 `filed + 1` 日起可用，申报当日和未来材料均不能通过。
4. 使用材料的字面金额独立进行精确有理数计算，原回答数值和单位与计算结果相等。

未满足条件就返回拒答；保留模型原先的拒答。不补检索、不补数值、不把正确答案填回响应。原始模型解释仍保存在记录中，发布解释替换成确定性的验证说明，避免让未经核验的自由文本随数值一起获得“通过”标签。

最后才调用未修改的旧 `score_answer` 进行评分。这个顺序避免把金标准写进接受条件。

## 结果及覆盖损失

| 指标 | 原始输出 | 加证据门后 |
|---|---:|---:|
| 按原评分规则判对 / 全部计划单元 | 23/36 | 30/36 |
| 申报前正确拒答 | 5/18 | 18/18 |
| 申报前越界数值回答 | 13/18 | 0/18 |
| 申报后正确数值回答 | 18/18 | 12/18 |
| 申报后正确且有完整材料支持 | 12/18 | 12/18 |
| 采纳未来材料的响应 | 1 | 0 |

门禁接受原来的 12 个有完整材料支持的回答，拦截 19 个原回答，并保留 5 个原拒答。

**代价是申报后的回答覆盖从 18/18 降到 12/18。** 被拒绝的 6 个回答全部是闭卷条件下数值正确但没有材料引用的回答。门禁没有创造新的正确财务事实；它收紧了证据要求，以牺牲覆盖换取可审计的支持。

| 原始条件 | 原判对 | 门禁后判对 | 申报后回答覆盖变化 |
|---|---:|---:|---:|
| 不给材料 | 6/12 | 6/12 | 6/6 → 0/6 |
| 提供未过滤材料 | 11/12 | 12/12 | 6/6 → 6/6 |
| 按截止日过滤材料 | 6/12 | 12/12 | 6/6 → 6/6 |

不能只展示 `30/36` 而省略覆盖损失，也不能称“模型准确率从 64% 提升到 83%”。这是对已经曝光的小型开发试点施加确定性系统规则的结果。6 道题还共享 3 个披露事件，36 个输出不是 36 个独立样本。

它支持一个工程判断：仅过滤检索材料不足以约束模型的记忆回答，结果发布层还需要完整引用和计算核验。但严格证据门需要配合更好的材料检索才能提升覆盖；本轮没有实施或评价检索修复，也未构造所谓 `36/36` 的补答成绩。

## 复现

```bash
# 核验旧的真实调用记录，零调用
python scripts/verify_pit_release.py

# 从同一原始记录重新计算门禁；与发布结果逐字段一致
python scripts/replay_pit_gate.py --verify

# 人工反例：无引用、缺操作数、未来或当日材料、冲突值、错公司、数值/单位错误
python -m unittest research_workbench.test_pit_gate_replay -v
```

脚本默认不覆盖现有产物。需要另存一次重放时，显式指定新的 `--output` 和 `--summary` 路径。记录包含旧数据集、旧 trace、旧结果与门禁代码 SHA-256，可区分原始模型实验和后续系统干预。
