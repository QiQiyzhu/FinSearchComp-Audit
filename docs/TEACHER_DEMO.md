# FinSearchComp-Audit：3 分钟教师演示稿

## 演示目标

三分钟内让老师明确四件事：

1. 研究问题不是“再做一个金融聊天机器人”；
2. 本项目检查金融 Agent 的证据是否满足时间、期间、版本和单位约束；
3. 目前已有 100 条受控实验、四个策略、指标和逐证据 trace；
4. Claude 的 1题×4策略真实门禁已通过，正式扩展仍需控制费用与样本边界。

## 第 2 页：时间可靠性实验（约 75 秒）

打开：

<https://qiqiyzhu.github.io/FinSearchComp-Audit/temporal-audit.html>

讲解四类人工冲突：

- 未来证据：发布时间晚于问题截止日；
- 错期间：例如题目问 2023 财年，证据来自 2024 财年；
- 错版本：初步值、修订值或最终值混用；
- 错单位：百分比、基点、百万美元等口径不一致。

可以直接说：

> 普通 Agent 在受控挑战条件下会采用所有扰动证据。只加时间 Prompt 有改善，
> 但不能处理期间、版本和单位冲突。元数据过滤器进一步提升，而完整证据验证器
> 对四类字段逐一检查，并在没有安全证据时拒答。

解释 TRG：

> Temporal Robustness Gap 是干净条件准确率与挑战条件准确率的差值。
> 越接近零，说明方法面对受污染证据时越稳定。

## 老师可能追问

### 为什么不直接跑 20 题 × 4 策略？

先用 1 题检查模型权限、搜索引用格式、发布日期字段和费用，再逐步扩大。
这不会影响受控实验，二者分别回答因果有效性和外部有效性。

Claude 因为 citations 与 Structured Output 不能同一请求启用，所以每个策略固定为
同一模型、同一 effort 的“搜索研究 + 结构化归一”两个阶段。1×4 上限为 8 次 HTTP
请求；20×4×3 上限为 480 次 HTTP 请求和 720 次 Web Search。

### 100 条数据是不是太少？

这是第一版 mini benchmark，用于验证任务定义、扰动设计和指标是否有效。
投稿版本需要扩大问题、领域、来源和模型覆盖，并做人工一致性检验。

### 完整验证器为什么能达到 100%？

因为当前受控集的日期、期间、版本和单位都有明确标注。这个结果说明规则实现正确，
不等于开放网页中的所有元数据都能自动获得。

### 与 Look-Ahead-Bench 有什么区别？

Look-Ahead-Bench 关注金融模型或策略在不同时期的前视偏差；本项目把问题推进到
金融研究 Agent 的检索链路，检查每条证据在问题指定时间点是否可用。
