# FinAgent 金融研究工作台：面试演示指南

入口：[项目首页](https://qiqiyzhu.github.io/FinSearchComp-Audit/) · [一键体验](https://qiqiyzhu.github.io/FinSearchComp-Audit/workbench/) · [部署说明](../README.md) · [研究到工程的映射](WORKBENCH_RESEARCH.md)

## 90 秒介绍

> 我把原来的金融检索实验扩展成了一个可以直接体验、部署和检查结果的研究工作台。用户选公司、输入问题和截止日，系统从 SEC 财报数据中提取年度指标，计算增长与盈利情况，给出带引用的报告和后续研究建议。
>
> 我重点处理的是三个容易被聊天界面掩盖的问题：数字所属期间不一致、历史研究混入后来披露的信息，以及模型给出无法回查的结论。因此公司、指标、期间、单位和申报日期都进入数据契约，关键计算交给 Decimal，派生指标保留操作数和证据引用。DeepSeek 在已有事实中做选择与排序，并选择下一步核验动作；展示文字来自确定模板，基本面方向也有公开规则。
>
> 工程上，我补齐了 FastAPI 服务、SQLite 任务记录、调用配置和可部署前端。公开页面有无需密钥的固定演示，完整服务可以调用真实 SEC 数据与 DeepSeek。页面会区分演示、历史数据加模型以及在线数据模式。
>
> 这个版本的价值是把数据到报告的链路做完整并且可检查。目前仍主要覆盖年度基本面，没有证明投资收益，也没有把论文训练方法和商业平台的数据覆盖说成已实现。

## 五分钟演示顺序

| 时间 | 操作 | 让面试官看到什么 |
|---|---|---|
| 0:00–0:40 | 从项目首页进入工作台，选择 Microsoft 演示 | 一次完整研究任务的输入与交付物；页面明确显示历史数据和演示模式 |
| 0:40–1:40 | 查看财务指标，打开一条证据及其 SEC 来源 | 数值对应哪家公司、哪个期间、哪个申报；来源可点击核对 |
| 1:40–2:30 | 查看增长、利润率或现金流的公式与引用 | 派生数字的操作数有依据，展示值与计算责任清楚 |
| 2:30–3:15 | 查看观点、风险与研究缺口 | 从已知基本面得到条件性判断，缺少估值与价格时保留问题 |
| 3:15–4:15 | 启动本地服务，在可用模式中提交一条新任务 | API、任务状态、数据与模型调用的真实执行，不把静态示例解释为在线生成 |
| 4:15–5:00 | 打开保存的报告、轨迹或导出结果，再展示一个缺失数据案例 | 系统不仅有成功路径，也能留下可诊断的失败与不完整结果 |

浏览器公开体验优先用固定案例。真实调用需要完整服务与服务端配置；启动方法以[仓库首页](../README.md)为准，本地默认入口为 `http://127.0.0.1:8090`。不要在面试共享屏幕中展示 `.env` 或密钥。

一个已检查的时间边界案例：连接完整服务，选择“AI 研读”或“实时研究”，公司选 `MSFT`，问题填“分析微软 FY2024 的收入增长”，截止日填 `2024-07-29`。FY2024 10-K 在次日才申报，因此应显示该期间证据不足，不能使用后来披露的数值回答。把截止日改到申报日之后，再查看同一个期间如何获得证据。公开的“历史案例”按钮仅回放固定问题，不执行这项修改后的请求。

## 三种模式一定说清楚

| 模式 | 数据 | 模型 | 适合展示 |
|---|---|---|---|
| Demo | 仓库内固定 SEC 历史样本 | 不发生实时模型调用 | 无需配置即可理解产品和证据结构 |
| Snapshot | 已保存的历史 SEC 数据 | 配置后调用真实 DeepSeek | 隔离实时数据网络变化，检查真实模型对已有事实的编排 |
| Live | 服务端查询 SEC，可能使用有效缓存 | 按服务端配置调用模型 | 检查实际连接、数据筛选和端到端执行 |

在线取回一个 SEC 响应，不代表所选财务期间是最新，也不代表数据是行情。演示 cutoff 为 `2024-11-01`；抓取时间与截止日各有用途。

## 最值得讲的工程决策

**为什么从 SEC 年度数据开始？** 它把事实和来源组织成明确结构，适合验证时间、单位、期间与计算。相应代价是覆盖面有限，当前服务不能回答所有新闻或市场问题。扩展新的数据源时，应先确定数据契约和授权，再接模型。

**为什么数值不交给 LLM？** 模型生成一段正确文字与数值计算正确是两个问题。规则计算能保留精确操作数、公式和舍入方式，模型故障也不会改变已经得到的财务事实。当前 DeepSeek 只能选择允许的事实 ID 与后续动作 ID；这是一个可检查的编排边界，代价是解释能力有限，尚不能自动写开放式行业研究报告。

**基本面方向是怎样产生的？** 当前采用简单公开规则：范围和证据充分时，正收入增长与正营业利润率支持继续研究；收缩或亏损触发审慎信号。这是研究优先级提示，未经预测效果验证，不应包装为模型对股价的独立判断。后续要加入更完整的现金流、估值与业务风险证据，再评价这些规则是否有用。

**为什么有引用还要检查日期？** 同样是“FY2024 营收”，一份年报可能在截止日之后才提交。系统同时看财务期间和申报时间。当前按日筛选，不是精确到 SEC 接收时间的盘中可用性研究。

**为什么先用 FastAPI 与 SQLite？** 当前是单机部署和面试可体验范围，容易安装、检查和复现。更大规模需要验证跨实例限额、持久任务队列、租户隔离和数据库备份；接口存在不等于这些能力已经成立。

**为什么要保留 Demo？** 面试官可以不提供凭据就了解核心行为。Demo 必须清楚标注固定样本；它不用于证明实时检索质量、调用延迟或模型稳定性。

**论文用到了哪一层？** EvidenceLoop 启发了证据标识与验证意识，Deliberative Searcher 提醒我不要混淆模型信心和可靠性，FinKario 启发了带实体与时间的金融数据组织。约束 RL、事件图和多轮验证不在当前实现范围，具体映射见[研究说明](WORKBENCH_RESEARCH.md)。

## 两个可深入讨论的真实问题

**相似名称的财务科目，口径可能不同。** NVIDIA 年报中的 PP&E 与无形资产合并支出不能直接当作所有公司的 PP&E 现金支出。当前选择不以这个混合科目填补缺失字段，避免计算出看似完整、实际不可比的自由现金流。原始数值与出处见[演示数据核验记录](WORKBENCH_RESEARCH.md#演示数据核验记录)。

**日期筛选不等于“完美历史数据库”。** 今天下载的 Company Facts 是今天的聚合响应；从中选出截止日前的 filing，是对申报可用时间的限制。若要研究财报重述、当时 API 状态或盘中策略，仍需保存原始申报版本、接收时间和历史快照，分别验证这些时间语义。

## 回答效果与下一步

面试时把证据分成三类展示：本次服务的测试及真实运行记录；原 ATLAS 实验的冻结协议和逐题结果；论文作者公开的研究结果。这三者各自说明不同问题。不要说“工作台准确率 100%”“已消除幻觉”“支持生产高并发”或“能稳定跑赢市场”，除非有对应范围的独立验证。

下一步先建立独立的报告质量测试集，同时检查数值正确、引用支持、回答覆盖、拒答与解释越界；再接有明确授权的新闻和电话会资料，验证事件抽取与多轮证据检查。部署层面，应围绕真实负载补齐任务恢复、租户认证、成本控制和可观察性，并用故障注入及压测记录证明效果。
