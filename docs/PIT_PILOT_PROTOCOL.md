# SEC 财报时点配对试点：实验协议

协议日期：2026-09-26。研究路线与相关工作见 [给老师的研究方案](PIT_RESEARCH_PROPOSAL.md)，交互入口为 [时点评测工作台](https://qiqiyzhu.github.io/FinSearchComp-Audit/workbench/pit.html)。本协议在本轮真实模型调用之前写定；冻结题包、提示词与原始响应随运行记录保存。

## 测什么

在同一份指定 SEC 10-K 的申报前后，模型能否遵守历史证据边界，并在材料可得时给出正确数值？改变输入证据，观察数值正确、该拒答时拒答、引用越界分别怎样变化。

这是小样本、封闭材料的**时点证据合规试点**。它没有按月估计模型知识边界，没有开放网页检索，也没有测量投资收益。`closed_book` 是本试点的无材料对照；它仍接收历史截止日与指定申报范围，不能替代无时点限制的知识回忆测验。

## 数据与时间

- 三家公司：Microsoft、Apple、NVIDIA；每家 FY2024 营业收入与营业利润率，共六道基础问题。
- 每题明确报告期起止、财年标签、单位和唯一 `accession`。每份申报是一个事件簇，因此六题只有**三个披露事件**。
- 每题两个截止日：指定申报日 D 的前一天 D−1 与后一天 D+1。不使用申报当天，避免把只有日期的元数据解释成精确发布时间。
- 证据来自本仓库已保存的 SEC Company Facts 原始 gzip；锁定标签、期间、申报编号、申报日期与原始值。原始下载日期与历史申报日期分开保留。今天保存的历史行不等于在历史当天保存的数据库快照。
- 本试点的“前期不可回答”仅相对于**指定 10-K 证据范围**。同一数字可能已在更早的财报电话会、业绩公告或 8-K 中公开；没有检查这些来源，不能声称当时全市场都不知道。
- 本轮没有真实重述案例、全文表格定位或盘中 `accepted_at` 验证。后续扩展时分别补齐，不能把发布日期过滤包装成完整的版本回滚系统。

证据保存 `period_start/end`（财务所属期间）、`filed`（申报日期）、`retrieved_at`（下载时间）、原始文件指纹；运行另存 `evaluated_at`、请求模型名和响应模型名。日期缺失、版本无法确认和数值缺失不能相互替代。

## 三个实验条件

| 条件 | 模型收到的材料 | 用途 |
|---|---|---|
| `closed_book` 无材料 | 问题、截止日、指定申报信息；没有数值证据 | 观察无检索材料时的回答行为；不据此直接断言参数记忆来源 |
| `unfiltered` 未过滤材料 | 同一冻结财报证据包，D−1 也展示尚不可得的申报行，保留真实日期 | 检验模型能否仅凭相同时间约束提示识别未来材料 |
| `pit_filtered` 时点过滤 | 同一证据包经过 `filed <= as_of` 过滤 | 检验限制输入证据后的正确性与可回答率 |

三个条件的任务指令、模型、温度、输出格式相同，只改变证据集合。D+1 时后两个条件收到的材料相同，是输入构造的检查；仍为独立调用，不假定服务端完全确定。每次调用独立上下文，不把其他条件的回答传给模型。

总计划为 **6 题 × 2 截面 × 3 条件 = 36 次请求**，单模型、单次采样。调用次数设置硬上限，无自动重试。失败与格式无效保留在记录里，不偷偷更换答案或补跑至成功。浏览器只回放结果，不发起付费模型请求。

## 冻结与金标准

先写定字面财务操作数和答案，再从原始 SEC 行核对唯一申报；使用独立 `Fraction` 运算计算营业利润率，不调用工作台的选数或计算函数。金额单位为 USD；利润率使用百分数，两位小数。最终公式与数值容差以冻结题包和评分代码为准。

冻结文件保存 SHA-256。运行保存题包和提示词指纹、完整请求消息、原始响应、模型响应 ID、时间、token 用量及错误状态；不保存鉴权头或密钥。后续修复若改变题目、输入或评分，必须产生新版本，保留本次首次记录。六道题是项目自编且开发者已知的试点题，**不是隐藏测试集**。

## 分开计分

| 指标 | 分母与解释 |
|---|---|
| 时点决策正确 | 有效结构化响应；D−1 应拒答，D+1 应给正确数值与单位。引用质量另计 |
| 发布前正确拒答 | 有效 D−1 响应；反向同时报告发布前仍回答的次数 |
| 发布后数值正确 | 有效 D+1 响应；不得用“只统计答对的已作答题”抬高成绩 |
| 未来证据采纳 | 在响应中引用申报晚于截止日的证据；输入展示未来材料与输出采纳分别记录 |
| 不支持的引用 | 返回不存在或未提供的证据 ID。数值正确不能抵消引用失败 |
| 调用完成与可评分覆盖 | 所有计划请求；错误和无效 JSON 单列，同时披露计划/尝试/完成/可评分分母 |
| 成本 | 实际请求数与 token；没有核验适用计价时不臆算人民币费用 |

“发布前仍回答”只证明违反本题的证据范围和时点要求；可能来自记忆、猜测、未来输入或忽略指令，不能仅凭这一项判定训练污染。自由文本解释暂不由模型裁判计分，未引用的文字也不被声称已完成全面语义审计。

同一事件的多个问题与前后条件有关联；本试点展示逐题配对与分子/分母，不用 36 次调用冒充 36 个独立事件，也不据三个事件推断显著性或模型排名。若三个条件表现相同，照实保留零差异，这同样能指导下一轮更有区分度的数据设计。

## 复现与下一轮

具体命令见 [实验模块说明](../pit_benchmark/README.md)。离线模式验证题包、原始证据与评分，输出未运行计划；只有显式执行模式才读取本机模型配置并发起调用。已发布结果可直接下载、重算指标，重算不应调用模型。

下一轮先扩到更多发行人和独立披露/修订事件，按事件划分开发与隐藏测试，加入真实更正版、未知时间、部分证据、多跳计算和日内时间边界。新闻与研报再增加首次发布证明、版本存档、授权记录和人工复核。另设闭卷月度题批次测行为知识画像，不能把本试点的前后两个截面误画成模型知识截止曲线。
