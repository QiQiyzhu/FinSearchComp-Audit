# 指定财报语料的时点试验

这是 6 个问题、3 份真实 SEC 10-K 的开发试点。每个问题在申报日前一天与后一天各运行三种条件，共计划 **36 个请求**：不提供外部材料、提供未过滤材料、只提供截止日前材料。三种条件使用相同任务和截止日指令，只改变材料集合。

本试点的证据范围明确限定为题目指定的 accession。申报日前输出数字记为“相对指定财报语料不受支持的历史回答”，不表示该数字当时未曾通过业绩公告等其他渠道公开。历史日期提示和闭卷回答不能测出模型的真实训练截止日。申报日只有日粒度，因此没有申报当日的试验，不推断盘中信息可用性。

## 冻结与独立核验

- `fixture.json` 保存协议、6 个字面 SEC 操作数、来源、抓取日、申报日、精确 accession、6 个问题和金标准。
- `manifest.json` 固定题包 SHA-256 和冻结时间。这些是项目已经接触过的 FY2024 财务事实，不称为未见保留集。
- `pilot.py` 逐行匹配仓库原始 SEC gzip，核对来源 SHA、公司、期间、申报日、accession、标签与金额；利润率用 `Fraction` 独立复算，不导入工作台的选数器或计算器。
- 原始响应抓取于较晚时间，按历史申报日筛选；不是在历史时点保存的完整数据库。
- `run.py` 保存完整请求与供应商响应、UTC 运行时间、模型请求名及返回名、结束原因、请求/响应 ID、token、延迟和失败。别名不构成对模型底层检查点的独立证明。

## 使用

从仓库根目录运行。默认离线，只核验题包并生成 `not_run` 计划，不加载密钥、不调用模型，不产生模型成绩：

```bash
python -m unittest discover -s pit_benchmark -p 'test_*.py' -v
python -m pit_benchmark.run --output build/pit-plan-new.json
```

明确执行真实试点时，读取根目录 `.env` 的 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL` 和 `DEEPSEEK_MODEL`，其余参数固定为 `temperature=0`、`max_tokens=700`、关闭 thinking、无重试。最多 36 次请求；任何 HTTP 401、402、403 或 429 都提前停止。失败不会自动重试或被改记为拒答。不要用新的输出名重复运行来挑选成绩。

```bash
python -m pit_benchmark.run --execute --output docs/verification/pit-pilot-live-20260926.json
```

默认在同目录生成 `.trace.jsonl`。每次请求发出前先追加请求记录并刷盘；响应随后追加。所有产物要求新文件名，已有记录不会覆盖。可用 `--max-calls 1` 限制开发调用，但这不构成完整试验。正式运行前应提交冻结题包、协议和代码；正式结果出来后不更换题目或评分规则。

重放已存 trace，不读取密钥、也不调用 API：

```bash
python -m pit_benchmark.run --replay docs/verification/pit-pilot-live-20260926.trace.jsonl --output build/pit-replay-new.json
```

重放校验题包哈希、原始请求是否完全符合协议、响应文本哈希和记录的评分代码版本，再从原始模型响应重算所有结果并核对汇总。若调用中断，已有请求而缺响应的单元记为错误。完整复现需要记录中指定的代码版本；`pilot.py` 和 `run.py` 修改后不应用新逻辑冒充旧评分。

## 评分与分母

- 申报前：正确拒答 / 已评分的前期单元；另列相对该财报语料的越界回答。
- 申报后：正确数值与单位 / 已评分的后期单元。后期拒答是未完成任务，不是时间违规。
- 未来证据采纳：引用未来材料的单元 / 实际暴露未来材料且已评分的单元；没有暴露时是 **N/A**。
- 引用不存在或未提供的 ID 不算证据支持。数值正确与来源支持分别计分，闭卷正确答案可以没有文档支持。
- 材料支持要求完整操作数及有效引用；联合指标还要求数值正确。这里没有用另一 LLM 裁判解释文本。
- 汇总同时保留计划、尝试、完成、错误、无效输出和已评分分母。正式报告还应以全部计划单元计算任务成功率，避免通过排除失败美化结果。

三种条件每种只有 6 道问题，且同一公司两道问题共享同一份申报。36 个调用并非 36 个独立问题。本试点不评价月度知识变化、开放新闻/研报检索、模型总体排名或投资回报。
